# Go Memory Models & Pointer Semantics

Unlike languages with garbage-collected reference semantics (such as JavaScript/TypeScript), Go gives software engineers explicit control over **value vs pointer semantics** while retaining safety.

## Value Semantics vs Pointer Semantics

In Go, **everything is passed by value**. When you pass a variable into a function, Go creates a copy of that value on the stack.

```go
package main

import "fmt"

type Counter struct {
	Count int
}

func IncValue(c Counter) {
	c.Count++ // Operates on a copy!
}

func IncPointer(c *Counter) {
	c.Count++ // Mutates caller memory!
}

func main() {
	c := Counter{Count: 0}
	IncValue(c)
	fmt.Println(c.Count) // Prints 0

	IncPointer(&c)
	fmt.Println(c.Count) // Prints 1
}
```

## Key Principles

1. **Stack vs Heap Allocation**: Small variables without escape stay on the stack (zero GC overhead).
2. **Pointers (`*T`)**: Pointer variables store the memory address of another variable.
3. **Escape Analysis**: If a pointer outlives its stack frame, Go's compiler automatically moves (escapes) it to the heap.
